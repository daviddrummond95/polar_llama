## Why this matters

The repo has THREE disagreeing Python dependency lists (`requirements.txt`,
`pyproject.toml` `[dependency-groups]`, `tests/requirements.txt`), of which
only the first is actually installed by CI and the Makefile — the other two
silently rot. `Cargo.lock` is tracked yet listed in `.gitignore`; `uv.lock`
exists on disk but is ignored and untracked, so no Python resolution is
reproducible. And ruff/mypy are installed everywhere but have NO configuration
and run with `|| true` — worse, CI runs `ruff check . --fix`, which MUTATES
files inside the CI workspace that are never committed, so lint "passes"
while doing nothing. After this plan: `pyproject.toml` is the single source
of truth for dev dependencies, `uv.lock` is committed, ruff and mypy have
real configs, the violation backlog is fixed/baselined, and both tools gate
locally (`make pre-commit`) and in CI.
